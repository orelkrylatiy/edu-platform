# SA Interview Scorecard

[[Middle System Analyst Roadmap]] · [[SA Practice Lab]]

## Оценка (учебная, не стандарт работодателя)

0 — не знаю; 1 — узнаю термин; 2 — объясняю с примером; 3 — решаю незнакомую практическую задачу без подсказки; 4 — дополнительно защищаю альтернативы, ограничения, failure cases.

## Core questions (без готовых ответов)

**Requirements:** FR vs NFR? Бизнес-правило vs требование? Use Case vs User Story? Как выявить и проверить требования? Как разрешить конфликт? Как оценить влияние изменения? Дефект vs CR?

**API:** Как составить data mapping и правила валидации? Что такое SOAP Envelope/Fault, WSDL и XSD? Как безопасно изменить контракт? REST constraints? PUT vs PATCH? Что означает idempotent? 401/403/404/409? JSON types? Null vs omitted? API pagination? Что в OpenAPI? SOAP vs REST? Webhook vs polling? Повтор платежа после timeout?

**DB:** DDL/DML/TCL? ROW_NUMBER vs GROUP BY? Как читать Seq Scan / Index Scan? PK vs FK? Связь M:N? 1NF–3NF? Аномалии? JOIN vs LEFT JOIN? WHERE vs HAVING? COUNT(*) vs COUNT(col)? Почему индекс ускоряет чтение и замедляет запись? ACID и уровни изоляции? Lost update? SQL vs NoSQL? OLTP vs OLAP?

**Modeling:** когда UML sequence, BPMN, state machine, ERD? alt/opt/loop? XOR vs AND? Pool vs lane? Sequence vs message flow? Допустимые переходы статусов?

**Integration:** Kafka vs RabbitMQ? Topic/partition/offset/group? Порядок? Retention? ACK/NACK? At most/at least/exactly once? Retry vs DLQ? Дубликаты, идемпотентность и Outbox?

**Architecture:** как сформулировать и измерить P95/RPS/availability? Как проверить доступ к чужому объекту? Какие тесты и данные в логах нужны для диагностики? монолит vs микросервисы? Cache/TTL? API Gateway vs load balancer? Репликация vs шардирование? Timeout/retry/circuit breaker? Authn vs authz? JWT vs OAuth/OIDC? Чем SLA отличается от SLO? Как обнаружить и локализовать сбой?

**Experience:** Почему системный анализ? Какие аналитические задачи действительно выполнял как разработчик? Как уточнял контракт, взаимодействовал с backend/QA, разбирал ошибки? Какой компромисс сделал и почему? Где нет коммерческого опыта — назвать учебную практику явно.

## Рубрика комплексного кейса

Оценивать отдельно от теории: 0 = отсутствует/ошибочно, 1 = частично, 2 = самостоятельно и корректно.
| Критерий | 0–2 |
|---|---|
| Уточнил цель, акторов, границы, assumptions | |
| FR/NFR измеримы, есть business rules и exceptions | |
| API семантически корректен, описаны ошибки, повтор, маппинг при необходимости и доступ | |
| ERD/SQL корректны, учтена конкурентность | |
| Диаграммы отражают контракт и состояния | |
| Обработал timeout, дубликат, сбой зависимости; NFR и способ проверки | |
| Обосновал альтернативы, не переусложнил | |
| Объяснил решение ясно, реагирует на изменение условий | |

Критические ошибки независимо от суммы: существенная неисправленная ошибка SQL, непредотвращённая двойная оплата/потеря данных, обход прав доступа, противоречие модели и API, выдуманный опыт, неспособность обозначить ключевые assumptions. Оговорку или ошибку, которую кандидат сам обнаружил и исправил, оценивать по итоговому решению; не считать любое устное спотыкание провалом.
Условная цель: каждый из двух разных комплексных mock ≥13/16 без критических ошибок, отдельно пройден незнакомый SQL/API drill, повтор слабых тем без подсказки. Не подменять результаты практики средним баллом за теорию. Для SQL drill — четыре новых задачи на LEFT/anti-join, агрегаты, CTE/subquery и latest-row; все корректны после самостоятельной проверки. Для API drill — 3–5 операций, согласованные типы, status/error schema, авторизация, обработка повторов; проверка валидатором если оформляется OAS. Не обещает прохождение реального интервью.
